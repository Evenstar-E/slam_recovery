## 1. 唯一主线和禁止提前启动的范围

**先完成 MM-LINS、FAST-LIO2、LIO-SAM、ORB-SLAM3 四项上的全部工程需求与论文证据验收，再开展 FAST-LIVO2 适配。** 四项的内部执行先后可按已有环境和真实依赖安排，不能因较难或负结果跳过任一项。

在四项全部验收前：

- 不新开 FAST-LIVO2 运行、构建、适配、调试、参数实验或 v10/v11 及以后版本的后续开发/验证任务；不以“补日志”“补一个字段”“下一次 run 顺带导出”为由绕过顺序。
- 保存 FAST-LIVO2 的现有源码、快照、已完成运行和负结果；允许只读引用既有原件，但不得让其支线取代四宿主主线。
- 已经实际启动的任务仅沿原有更早停止预算安全收尾，保留结果，不续跑、不延长、不自动重试。不得据文档猜测进程状态或终止不明进程。执行侧需回复实际在途任务、停止点及落实情况；本次 Git 发布不等于已确认远端停止。
- 四项未全部通过时，不自行返回 FAST-LIVO2。任何宿主删减、需求豁免、阈值放宽或更早恢复 FAST-LIVO2，均须用户明确改变此决定；代理、提交说明、沉默或旧时间授权不能替代。

## 2. “全部需求解决”的验收依据

沿用 [主线 A/B 评分与验收标准](MAINLINE_PROGRESS_STANDARD_20261109.md)，不新造低门槛替代：

- **工程轴 A1–A12**：输入与身份、原生执行、在线检测、完整可信检查点、隔离与帧归宿、历史重处理、独立准入、原子提交、多事件撤销、接回后持续运行、同步评价和复现预算。
- **论文轴 B1–B12**：问题与保护必要性、保护正确性、检测能力、修复净收益、门的增量价值、因果机制、正常代价/有害风险、重复与不确定性、未参与开发环境泛化、公平完整基线、同一原生在线链与成本、独立复现。

为四个宿主分别记录上述 A/B 需求的当前阶段、原件和剩余条件。沿原 0–3 阶段定义，3 表示该项冻结范围内的全部条件通过；所有适用项完成且未解决的范围争议获用户裁决后，才报告该宿主整体验收完成。不能用平均分、测试数量、一次 accepted、最终 HEALTHY、原生第二事件观察或共享组件单测抵消关键缺口。

公共组件证据可以有明确版本地复用，但原生适配、真实输入接回、第二事件、效果和成本必须有对应宿主证据。不同传感器/地图表示造成的指标适用性要具体说明；**不能自行用 NOT_APPLICABLE、缺 GT、缺数据或“以后再做”删掉需求**。确有不适用项或无法满足的条件，提交具体范围与替代证据方案给用户决定；在此之前保持未通过，不默认放行 FAST-LIVO2。

宿主本身在退化下失败是需要保留的基线结果，不要求把原算法改成永不失败。要验的是我们声明的工程行为、修复收益和边界证据：成功修复、安全拒绝、未恢复、漏修、误干预分别报告，不能把拒绝或未知统计成恢复成功。科学门和既有支持范围不因新顺序放宽。
