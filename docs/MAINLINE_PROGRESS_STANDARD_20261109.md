# 主线评分、进度与验收标准

> every auto review needs read and plan to work on main line according to this table

本表将用户本次要求的两个目标分开记账：**A：完整闭环、可研究且可复现的实验原型；B：能够支撑核心论文主张的证据**。每次自动审阅必须先读本表，再根据最新代码和证据制定一个具体的主线推进计划。

## 1. 版本、范围和计分口径

- **评分基线**：[`7fc67cf6ca7eb57ae48919de742f7773bd940045`](https://github.com/Evenstar-E/slam_recovery/tree/7fc67cf6ca7eb57ae48919de742f7773bd940045)，2026-11-09 本次审阅评估。
- **发布所基于的主线**：`3fc10e995fa958365a02d73fb5f2419d69c9ec46`。它已包含评分基线之后的身份、共同集合、T1/T2 对照、对齐及收据检查更新。**本次仅发布标准，没有重新给这些更新打分；下表的“已有／缺口”均指评分基线，不能直接当作最新提交仍有同样缺陷。**
- **范围**：单宿主、有限且明确声明的退化类别、允许安全拒绝的 SLAM 研究闭环。不要求多宿主全故障覆盖，不包含完整真机导航控制或生产安全认证。
- 每轴 12 个工作包，每包 0–3 分，等权相加，满分 36。每项剩余阶段分为 `3 - 当前分`。这是**序数阶段分的审阅估计**，不是代码比例、剩余工时、恢复成功率或论文录用概率。
- “已有模块约六七成”与本表不是同一口径；本表要求原生闭环与可复现验收。负结果可以增加研究认识，但不会自动证明正向有效性。
- 本表不替换 P0–P5 或已有冻结科学门，不降低验收阈值。尚未声明的最小有效增益、非劣界限、延迟和成本上限，必须在确认性实验前冻结，不能看结果后改标准。

| 2 | 已有局部原生运行或条件性验证，但本项全部条件尚未闭合 |
| 3 | 冻结范围内的全部验收条件通过，来源与结果可追溯复现 |

## 5. 指标清单与验收解释

| 指标组 | 必报内容／分母 | 验收解释 |
|---|---|---|
| 身份与完整性 | 唯一 run ID；source/config/input/output SHA；实际消费数量、时间、分组；输出及缺测清单 | 错配、重复、空独立指标或缺必要证据不能 PASS；可追溯不等于算法有效 |
| 事务正确性 | 半提交数、pending 丢失数、版本不一致数、拒绝时可信状态变化；故障注入位置清单 | 在声明测试空间中应为 0，并有正/负例；不据有限测试宣称现实零风险 |
| 检测 | 事件召回、误报/小时、检测延迟 p50/p95、起点误差；所有声明事件含漏检/迟检 | 阈值在确认实验前固定；标签仅离线使用，不能以已知注入窗替代在线检测 |
| 端到端恢复 | 完成修复、验证、提交且持续运行通过的事件数 / 全部预声明 eligible 故障事件数 | 漏检、超时、缺测保留在分母；安全拒绝单列，不算成功恢复；不能事后改变 eligible 定义 |
| 验证门 | 有害错接纳率、有益错拒绝率及计数/区间；相同候选流的无门控对照 | 候选质量标签来自独立离线评价；不以候选自身或共享求解数据证明门有效 |
| 地图 | 固定 ROI 的覆盖、不支持比例、新增正确/错误几何、丢失正常几何；缺输出和代价 | 固定人口、单位和参考；联合报告质量/覆盖/损失，不把不同分母随意合成一个“净收益分数” |
| 轨迹 | 同一 GT 时间支持的 ATE、平移/旋转 RPE 与尾部；匹配、同步、对齐协议 | 没有合法 GT 就标未测；冻结 prefix 对齐与全轨迹拟合诊断分开，不以 gauge 或时间差解释成物理漂移 |
| 服务与成本 | 输出可用性、接回位姿跳变、中断、恢复延迟、峰值内存、积压和追赶、吞吐 | 1× 实时需实测持续处理能力；不以离线较快、单次启动或 loader 通过代替实时闭环 |

这些指标补充而不覆盖已有预声明标准。尚未冻结的数值阈值标 `UNDECLARED`，不得据本表擅自降低门槛。比例报告同时提供计数和适当不确定性；样本不足时直接说明。

## 6. 剩余主线：六组交付及依赖

这六组是本表的工作依赖，不是新的 P0–P5。每轮从最新证据选择一个最有区分力的主线交付；纯审计不能无限替代真实机制与闭环研究。

| 顺序 | 主线交付 | 对应行 | 最小通过条件／后继 |
|---:|---|---|---|
| 1 | 可信评价与事务边界 | A1/A4/A5/A7/A8/A9/A11，B2 | 核唯一身份、共同集合与同步；修影响目标运行的 pending、半提交、修复历史及切空间问题并给针对性反例。最新版本已修项直接核证据，不重复制造审计任务 |
| 2 | 区分重复不稳定的来源 | A2/A11，B6/B8 | 记录实际消费、初始化与线程条件；以受控对照区分输入分组、数值条件和评价问题。不要求所有并行程序逐位一致，也不把源码疑点当实证根因 |
| 3 | 一次真实原生完整闭环 | A3/A4/A6/A8/A10，B3/B11 | 同次宿主在线检测、实际检查点与重处理、公开提交、继续输入；同时验拒绝分支。组件串联图或离线重估不替代该交付 |
| 4 | 核心因果对照与安全代价 | A7，B1/B4/B5/B6/B7/B10 | 同输入四策略：原生／仅隔离／无条件修复接纳／完整门控；覆盖正常、退化、恢复尾段和两事件，报告全人口结果 |
| 5 | 冻结方法后测试新环境边界 | B8/B9 | 预声明未参与开发序列、阈值、重复与判据；同时呈现收益、拒绝和失败，不在测试集反复调参后称独立确认 |
| 6 | 冻结发布并独立复现 | A12，B11/B12 | 数据和环境可获取、预算可运行、核心表可重算；独立环境核版本/身份/数值/结论及成本 |

顺序表达证据依赖，不能变成“所有旁支都完成才允许做任何原生实验”。只有已证实破坏身份、状态安全、评价有效性或基本执行能力的缺陷可作为具体主线阻断；须给失败场景、最小修复与解除条件。任何执行仍遵守当前明确授权、暂停状态、资源预算及已有科学门。

## 7. 每次自动审阅必须产出的主线计划

先读取最新真实用户要求、当前提交与适用协议，再使用以下最小交接格式；与 [现有主线／旁支、自检协议](../REVIEW_AND_SIMULATION_PLAN.md) 第 10.10–10.13 节一起执行。

| 必填项 | 内容 |
|---|---|
| 版本与范围 | 实际审阅 SHA、比较基线、变更范围；区分源码检查、局部测试、归档读数和新原生测量 |
| 进度变化 | A/B 行 ID；原分→新分或维持；证据路径、命令、结果、仍缺验收；未复核行不得宣称重新通过 |
| 本轮主线成果 | 一个可验证的研究/闭环交付；仅日志、措辞或字段修复时如实写“主线结果未增加” |
| 下一主线动作 | 一个具体问题、执行内容、预期区分的假设、通过/失败条件；可执行时附既有授权及预算，未获授权只提计划 |
| 必须先做的保障 | 只列真实阻断及其最小解除工作；其他工程事项归为可并行或集中延期 |
