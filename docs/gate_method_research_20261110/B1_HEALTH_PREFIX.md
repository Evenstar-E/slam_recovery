# B-1 实验：健康前缀条件化的尺度（2026-11-10）

研究分支 `exp/gate-method-research`，不改生产门。本文只报 B 的第一版（B-v1）。

## 1. 冻结的规则（运行前写死，未事后调整）

只用节点在线能看到的量：自己的 NIS、可信关键帧数、地图点数。

| 项 | 值 |
|---|---|
| 合格帧 | 被判定（`node_map` 参考、NIS 有限）且 `trusted_keyframes ≥ 20` 且 `map_points ≥ 3000` |
| 前缀 | 时间序上**最初 30 个**合格帧 |
| 尺度 | `s = median(前缀上的 NIS)`（与 σ 标定同一约定：中位映射到 1） |
| 前缀完成前 | **不判定**（盲区），沿用节点 warm-up 的既有策略，只是加上支持度条件 |
| 前缀完成后 | `s` **冻结**，不再更新 |
| 告警 | `NIS/s` 超过检测器自身的尖峰限 `2.8/1.35 = 2.074`，或 CUSUM 超过 4.0；dwell=2 转隔离 |

**常数依据（来自既有开发证据，不来自本趟结果）**：σ\* 曲线在 21–50 关键帧触底，故取 20 作为"不再是年轻地图"的第一档；`map_points` 在 501–2000 档仍带启动期数值，3000 是第一档稳定值；30 帧约 3 s（10 Hz），够放一个中位数，又能在 onset 窗前开始判定；尖峰限与 dwell 是检测器原值，未动。

## 4. B-v1 做了什么、没做什么

**口径注（2026-11-10 补）**：本文的"窗前报警"指的是**注入窗之前的报警**，不是"误报"。
注入窗是**已知损害窗**，不证明此前输入完全健康——所以 onset 前存在真实轻度退化的可能没有被排除。
B-v1 首次 SUSPECT 的归一化 NIS 只有 2.11（刚过 2.074），恰好落在这个不能排除的区间里；
因此"16.8 s → 8.2 s"应读作**报警时刻后移**，不能读作"误报减少"。

- **做到的**：把**注入窗前的报警**提前量从 **16.8 s 减半到 8.2 s**。原因直接：前缀期不判定（5.7 s 盲区），把 1–2 关键帧那批 NIS 50–55 的帧挡在门外。
- **没做到的**：**仍然在 onset 前 8.2 s 报警**。
- **机制（帧级）**：首次 SUSPECT 的归一化 NIS = **2.11**，只比 2.074 高一点（原始 NIS ≈ 28）；
  随后的隔离由 **CUSUM** 触发（归一化 1.96 < 2.074，但 CUSUM 4.90 > 4.0）。
  也就是说，残余误报**不是原始 NIS 的尖峰**（基线那帧是 49.7，归一化 3822），而是**冻结尺度跟不上地图增长**：
  前缀中位 13.27，而 onset 前的 51–100 关键帧档中位已到 18.0，归一化 1.4–1.8，CUSUM 一路累积。
- **结构性结论**：**冻结前缀在原理上跟不上一张正在长大的地图**。这不是常数没调好，是"冻结"这个设计选择本身的结果。

## 5. 阴性对照（有实际触发路径，不是声明）

把前缀**故意取自退化窗内**（+6~+12 s 的帧，即规则本该排除的样本），尺度从 13.27 抬到 **1374.90**，
于是**窗口内一次报警都没有**（覆盖率 0.000）。这条路径真实存在且后果严重：把污染样本当健康校准，
检测直接失效。这正是 B 必须先固定"健康样本纳入条件"的原因。

## 6. 逐项结论

| 问题 | 结论 |
|---|---|
| B 改善的是窗前误报警、准入校准，还是二者？ | 只对**窗前误报警**有部分改善（提前量 16.8 s → 8.2 s）；**准入校准那一半 `BLOCKED`**——需要逐候选的尺度，归档没有 |
| 健康段是否被连带改变？ | 是：**5.74 s 盲区**，onset 前可判定帧从 168 降到 126，其中 42 帧仍被标出 |
| 污染会带偏吗？ | **会，且能失效**：污染前缀把尺度抬 100 倍，窗口内零报警（有实际触发路径） |
| 冷启动可用吗？ | 可用但代价明确：盲区 5.74 s，且这段正是"最想判定的启动期" |
| 现范围证据是否足够？ | 不足以下"B 可行/不可行"的结论，只能下"**冻结前缀这一形式不足以消除启动误报**" |
