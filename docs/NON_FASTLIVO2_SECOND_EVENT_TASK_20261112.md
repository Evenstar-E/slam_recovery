## 2. 每个宿主一次实际交付

同一次宿主实例、同一输入时间线：声明E1与E2 → 实际执行E1 → 真实输入继续/接回 → 实际遇到并处理或未能处理E2 → 尾段/退出记录。

第一批明确区分两层：

1. **宿主自身的原生多事件表现**：是否失跟、恢复/重建/继续、E2行为和尾段；没有恢复能力也记录实际失败，不为得到成功先大改算法。
2. **slam_recovery实际修复链**：若该宿主已有可执行接线则另列实际修复、原生状态/地图操作；没有则标NOT_IMPLEMENTED/BLOCKED。不能用第一层冒充第二层，也不能以第二层未完整适配挡第一层运行。

受控触发可用于已有接口验证，必须标CONTROLLED_INTERFACE_TEST；在线检测、自然事件、已知故障注入分别声明。E2=Experiment2、单窗同时多故障、两个分开的进程或两次离线重跑都不等同第二事件。

## 4. 自检与停止

每行给实际状态PASS/FAIL/BLOCKED；尚未启动写NOT_STARTED并给真实原因，证据缺失写UNCONFIRMED/UNAVAILABLE。NOT_APPLICABLE仅用于确实不适用的指标，不用于隐藏未运行宿主。

每次交付附：

- 实际命令、source/二进制/config/input/run身份、预算和退出原因；
- E1/E2定义、实际stamp/事件日志、同实例持续输入与输出、是否恢复、尾段缺失；
- 原生状态/地图动作能核到的范围，修复测量是否实际进入估计；缺GT不造质量数字；
- 失败、拒绝、崩溃、lost/缺帧与成本原件路径，PASS不只给测试/计数；
- BLOCKED具体到命令、环境或宿主文件/函数及最低解除，不以FAST-LIVO2未完成解释其他宿主未跑。

各次沿既有预算到停止点保留结果，不删除旧资产、不覆盖未提交工作、不为追成功改阈值。四项完成/具体执行断点逐项向用户汇报；实际修复原生整链首次完成仍立即单报，不混为本批矩阵覆盖。
