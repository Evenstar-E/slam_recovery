## 3. 当前主要问题

### P1：最新“数学不可达”论证混淆了评价量

位置：`docs/HANDOFF_20261110_gate_info_leg.md:25`、`docs/review_20261110_b10/hall01_confirmation_run.md`；实际计算：`slam_recovery/sim/transaction_manager_node.py:652`、`slam_recovery/core.py:677`。

逐帧分布的量是各帧自己的弱方向信息量（这些样本与最小平移特征值相同）。门内的 after 则是候选 FIM 在固定触发方向的二次型，且来自多帧矩阵平均后变换到共同评价基。逐帧“各自最小值的最大值”不构成后者上界，观测样本最大值也不是普遍可达上限。

反例：A=diag(1,5,5)，B=diag(5,1,5)，各自最小特征值均为 1；固定方向 v=(1,0,0)，before=vᵀAv=1，after=vᵀ((A+B)/2)v=3。after 超过逐帧最小值的最大值，并满足 after≥2×before。因此文中 66.78%/69.57% 只是某个分布计数，不能命名为“数学上不可能恢复的帧比例”。这不证明实际任何候选是优质或必能通过。

同理，3.0 位于观测分布内部不自动证明误拒：需要独立好坏标签及实际候选 after。门通常就应区分分布两侧，单看分位数不能判死。

方案 C 提议再做 per-point 归一，但 `validation/fim_and_holdout.py:73` 已有 `(J.T @ J) / len(p_valid)`。应先核指标物理语义、参考及点选择，而不是重复除点数。

处理：撤回过强推论，保留原始数字；不因该论证直接删除信息腿、放宽门或逐 bag 调参。当前信息门可能有实际局限，但正确的证据应来自同一固定候选流上的独立标签和消融。

### P1：UNAVAILABLE 与“可信准入”仍混在同一状态路径

位置：`slam_recovery/ros/recovery_node.py:591`、`:636`、`:674`。

没有独立参考时，日志记 UNAVAILABLE，但只要 manager 仍为 HEALTHY，函数仍调用 `step_healthy`，经过确认边距可进入 trusted；这不是仅仅保留原始帧。本机正常 on_pair 路径探针强制参考不可用，使用零边距隔离该策略：3 个 UNAVAILABLE、检测器调用 0 次、trusted=[0,1,2]。非零边距只延后提升，不增加检测证据。

这不表示全部未检测帧实际污染，也不表示归档中的 219 帧全部被提升：隔离已打开时走 pending，行为不同。问题是启动种子和后续失去参考的帧没有显式区分可信来源。如果错误位姿在参考不足时进入 trusted，之后会同时影响检测和验证门使用的参考。

最低解除：明确有限初始化种子的假设/来源；参考再次不可用时保留为未验证状态，或提供另一条明确可信证据路径。用“有参考→失去参考→重新获得参考”正常序列验证未验证帧不会悄悄成为门控参考。无需先建设生产级全部故障防护。

### P1：在线触发尚未给出可迁移的事件级资格

冻结 σ=0.884 时，room02 首报相对注入起点 −0.027 s；hall01 两趟分别 −10.399 s 和 −11.800 s。后者检验的是另一个更早的事件，不能作为同一注入区段的门控效果证据。

须区分“注入前报警”与“已独立证实健康段上的误报”：天然退化标签未齐，不能从时间先后直接断言那一段没有任何退化。当前足够支持的结论是：同一参数下，对目标注入事件的触发关联未闭合，尚不能给泛化召回/误报率。

hall01 ICP 另有独立失败：REFERENCE_TOO_SMALL、使用参考点 0、候选为空。它不属于有效好候选被信息门误拒。当前错误将空候选记作 invalid pose、after=0；后续统计应单列构造失败/缺测，不能混入门控拒绝率。

### P1（能力边界）：在线接线仍未闭合宿主恢复与自动再评估

位置：`slam_recovery/ros/recovery_node.py:763`、`:836`、`:1145`；`slam_recovery/ros/run_native_loop.sh`。

FAST-LIVO2 与 recovery node 在同一进程组、不同进程。recovery node 订阅 pose/scan、维护自己的事务地图，ROS 发布出口是状态 String；未见把修复后的状态/地图/bias/缓存恢复进宿主估计器的控制路径。“同进程组”不证明“宿主内部已回退并接回”。

每个 episode 第一次 decide 即设 decided=True；Mode3 等待后即使继续到帧，service/finish 也不会对该 episode 再构造/检验候选。作为一次性准入实验可接受；作为“等待新证据后自动恢复”的完整闭环尚未实现。

room02 ICP 归档：584/599 scans 配对、365 帧进入检测、219 帧未检测；1 个 episode、1 次拒绝、0 accepted、0 committed；拒绝后继续收到254帧，最终 WAITING_FOR_EVIDENCE。254 不是“成功接回后持续运行”的证据。hall01 两趟也无接纳。

### P2：候选质量、信息门价值和边界安全没有独立标签闭合

room02 ICP 对匀速外推的 25/25 帧内部残差更低，Wilson 下界 0.9023，平均残差约0.2629→0.0251。这证明该配对评分的改善，不证明真实轨迹/地图净收益，更不能排除候选质量问题；相邻帧相关性也不能忽略。

候选目前对整段应用一个刚体变换，无法修复段内随时间变化的相对轨迹畸变。该次 ICP=20 迭代、ITERATION_LIMIT、converged=false。不是宣称算法一定无用，而是不能把它当成所有退化轨迹重建能力的验证。

边界检查已改为含 elapsed time 的运动包络，避免把正常移动直接当瞬时跳变，这是合理修正。但源码明确 BOUND_ONLY，没有独立相对运动测量；通过包络不等于连续性/安全已经验证。

### P2：成本和复现目前支持“局部可运行”，尚不支持持续实时

归档 ICP 用时11.8277 s、全趟 wall77.587 s、最大消息积压116。11.8 s 超过2 s确认边距，但边距不必等于硬实时截止；不能只凭二者之比证明1×必然不达。当前也没有足够证据验收1×持续吞吐、积压追赶、成功接回后的成本。

此前加载压力不同的候选支持集/判决变化提示测量敏感性，但非单因素受控比较，不能把机器负载定为唯一原因。本轮未重跑原生。
