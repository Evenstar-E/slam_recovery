# VIO 备用进程重建与复验

2026-11-27（香港时间）。**备用真实退出后，在延长故障前健康后缀的一组连续 1× 回放中完成可信重建，后续成功交付短遮挡历史。原双事件时限仍未通过。整套稳定性矩阵复验仍未支持插件比原生更稳。**

## 本轮实现

- 后台重建在控制器检测到备用进程退出、I/O 失败或候选被退役后启动。活跃进程继续消费原始输入。重建按已提交的顺序回放，分别记录原图、仅累计 IMU、局部拟合和遮挡视图。若后台重放只差最后一帧，将它先移交有序备用队列，再接续新输入。在队列追到活跃宿主的时间戳及待提交 IMU 边界后，按原状态门核验移交后新到的 16 帧。接回资格在核验通过后恢复。已经进入未验证坐标的公开轨迹仍保留该标记。
- 复验版每帧只保存一字节的重放操作。在 EuRoC 中，物理帧和 IMU 区间从同一份静态录制重读。日志上限为 2,000 帧，超过范围后不能依赖它重建。这个方式覆盖控制器与活动进程存活、备用子进程退出的场景。主进程和控制器同时退出、断电、真机实时流的持久恢复还没验证。
- 主备通过 Linux 匿名内存对象复用同一物理帧的 ORB 关键点和描述子。默认试验环有 16 槽，包读取绑定代次及原来的像素和提取器签名。错过的包仍由原生提取补上。两进程各自执行匹配、跟踪和图优化。 [Linux memfd_create](https://man7.org/linux/man-pages/man2/memfd_create.2.html)
- 额外验证可选的历史特征缓存。它沿同一个重放范围保存已提取的精确特征，供崩溃重建复用。保持原辅进程与候选状态门，保留一个实时小环模式作对照。

## 特征传输消融

V2_01_easy、健康、950 对、同一套控制器，两臂顺序运行在同一组 CPU。每臂外部实收 864 帧，1,900/1,900 次相机特征请求命中，零输入丢失、零误隔离。只改变特征传输，保留原有图像和 IMU 传输。运行处在同轮测量环境，结果是一次配对。

| 特征数据进 Python 再转出 | 每方向 136,744,360 B | 0 B |
| 独立订阅端延迟 p95 | 11.096 s | 9.184 s |

## 早期重建反例

固定短长双事件、1× 输入，在第 12 秒真实 SIGKILL。第一版没有历史特征时重新启动备用，两窗均因未追平而拒绝。开启历史特征后，仍在两窗前忙于重放，收尾重放 824/950 帧。将终止时刻提前至第 4 秒，收尾 948/950 帧；同一第 12 秒终止的 0.5× 诊断达到 949/950，延长 1× 输入的反例达到 1,419/1,420，两者仍未交接。旧逻辑在两次前台检查之间总会新增一帧，按批调度时一直要求后台精确追到瞬时队头，导致近端一直差一帧。修正后最后一帧排在新输入前面，进程可继续跟随，状态准入保留独立校验。

950 对的两条历史特征臂实分配约 128.1 MiB，延长至 1,420 对在反例中实分配 194.1 MiB。特征缓存能省去重做的 ORB 提取，同时增加内存。保留缓存属于试验选项。

## 修正后的崩溃复验

在 V2_01_easy 中，只向本轮备用原生子进程发送 SIGKILL。注入器核对可执行文件以及该进程的父控制器。三组均观测到旧备用退出 −9，控制器与独立订阅器退出 0，各组输入无丢弃。

| 终止时刻与场景 | 输入 / 外部实收 | 备用回到活跃输入边界 | 实际候选结果 |
| --- | ---: | --- | --- |
| 第 12 秒，原 25/38 秒双事件 | 950 / 814 | 收尾仅重放 834 帧 | 两次备用不可用，安全拒绝 |
| 第 4 秒，原 25/38 秒双事件 | 950 / 814 | 57.33 秒墙钟后移交，已过原两事件，收尾前未再取得可信资格 | 两次备用不可用，安全拒绝 |
| 第 4 秒，延长健康后缀，53/64 秒双事件 | 1,420 / 1,296 | 52.84 秒墙钟后移交，收到截止传感器时刻 35.75 秒的状态。在第一事件以 16 帧取得备用资格 | 短遮挡 7/7 条惯性历史及 3 条视觉历史真实写回并由订阅器收妥，长遮挡证据不足后安全拒绝 |

长后缀组是根据早期反例追加的诊断。健康数据仍以 1× 独立送入，未为重建暂停。该组最大相邻交付间隔为 0.518 秒，但流已落后于输入，订阅延迟 p95 为 30.663 秒。两次复明到普通位姿实收分别为 24.455 和 30.209 秒。原坐标已核验输出的轨迹 RMSE 为 0.212 m，长窗后未核验的局部输出不计入此值。这组验证了重建和写回能闭合，也显示目前的前缀重放仍会耗尽实时预算。

## 整套稳定性矩阵

## 后续保存方式

1. **优先减少重启时需要重做的原生计算。** 按已验证的帧边界保存一次可恢复的状态，继续持久写入最近图像对、IMU 和物理帧编号。状态包括活动地图代次、关键帧图、当前和上一个跟踪帧、速度、偏置、预积分，以及局部建图和回环尚未提交的边界。先证明从该状态重放同一段健康输入能复现结果，再允许故障后的短后缀追赶。上游 Atlas 存档提供地图图结构的序列化入口，跟踪器和惯性运行状态要另行覆盖。 [ORB-SLAM3 宿主源码](https://github.com/UZ-SLAMLab/ORB_SLAM3/blob/0df83dde1c85c7ab91a0d47de7a29685d046f637/src/System.cc)
2. **只保存可再用的变化。** 大图按关键帧和地图点分块。两个状态间只追加变化块、被删除项和指向上一代的索引，定期合并成新基底以限制加载时间。把最近一段原始压缩图像和无损 IMU 日志留在 Linux 文件系统，大图写入和压缩放后台。只有状态和日志索引完整落盘后才发布这代，上一代继续可读。先测写入时的最长停发、实际落盘字节、复起时间及资格通过率。
3. **分摊健康期的重复开销。** 词典文本在本机为 145,250,924 B，两个进程各加载一份。共享只读二进制词典可同时减少启动解析和常驻内存，仍需验证词典查找结果相同。可进一步在双目特征可用时提前交给备用，使备用与主路后半段并行。先分别测启动时间、每帧输入到订阅端延迟、原生 CPU 时间和 PSS，确定哪个环节占主要成本。
