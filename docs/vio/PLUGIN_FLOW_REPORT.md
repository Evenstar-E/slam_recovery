# VIO 插件输入流水线、备用预算和回调

全部正式回放、外部订阅和评分在远程 WSL tzr@windows11 完成。宿主源码、原生求解器、标定和参数沿用冻结版本。VINS-Fusion 继续使用原生 be55a937 的估计器。OKVIS2 插件工作进程重新链接原有 a2ea0068 静态库，使用原生回调。每个回放臂使用相同的 EuRoC V2_01 前 950 对图像，双事件为 25–25.35 s 和 38–39.70 s 的全遮挡。输入时钟独立于宿主。真值只用于评分。

## 三项插件改动

1. 独立输入线程按原始物理帧顺序完成双目解码和原检测器计算。待处理队列最多 6 帧。主路取得同一帧的图像、检测结果和输入时戳。按原有等待规则使用到图像时间加 25 ms 的 IMU 数据。
2. 插件给两个宿主进程配置不相交的 CPU 集合。实测主路用 Linux CPU 0/2/4/6，备用用 8/10/12/14。角色互换时保留等量的分配。备用只有一个后台更新线程，使用有界的原始输入 FIFO。落后时记为不可接管。完成已排队的输入后，必须按物理帧号核验共同的预故障姿态、速度和偏置。缓冲超限的备用退出接管候选。
3. OKVIS2 在健康期每次输入只推进一次已有 processFrame，通过 setOptimisedGraphCallback 获取带物理时间戳的状态。下一帧检测可以与上一次优化重叠。回调通过待交付帧号核对，按顺序写外部订阅端。隔离时用原生处理接口完成待处理状态，禁止将未回调的帧当成已完成的接管边界。

初版在第二次隔离时等备用 50 ms，超时直接拒绝。最终版保留同一 50 ms 的同步等待上限，此后按新输入非阻塞复核备用是否补齐了原始输入。在原 1.5 s 候选窗口内将隔离输入保持待处理。当一模一样的故障前帧边界通过核验，候选才按顺序消费隔离输入。完整窗口内没补齐则拒绝。原有独立视觉准入门和惯性历史验收口径沿用。
