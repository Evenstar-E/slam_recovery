# ORB-SLAM3 VIO 稳定性矩阵

2026-11-27（香港时间）。运行了 32 个 1× 实验臂，输入均为前 950 对双目及归属 IMU，全部完成控制器和独立订阅进程收尾，输入丢帧为 0。旧版本部分候选退出码为 −9，单独计入失败。方案和评分口径在开跑前冻结。[实验协议](STABILITY_PROTOCOL.md)

主指标的分母包含距首次输入至少 8 秒的所有有 Vicon 支持的物理帧。只有在 1 秒内送达独立订阅端、原坐标已验证、位置误差不超过 0.50 m 的记录才计为及时可用。未收到、未验证和超时都保留在分母。报告的 p95 只对实际收到的帧计算，和该覆盖一起解读。本矩阵只有三条独立采集。分析按成组回放报告逐对差值，数据规模只支持对该宿主和这些配置作判断。

## 第一轮与改动后的比较

同步备用版在两条开发序列上的六个配对条件全部未过线。无注入没有误隔离，但增加了健康期排队。相对原生，V1_01/V2_01 的两次无注入及时可用位姿少 24/118 帧，订阅延迟 p95 多 13.49/10.22 秒。原组和双短窗也都降低了及时有效覆盖。V1_01 短窗存在回退前后不足以建立保留区几何证据的拒绝。V2_01 的双短窗确实可两次接纳，整段及时覆盖仍少 104 帧。

改进版在健康期提交最多 8 个镜像任务，只有积压触及上限或候选需要同一物理帧时才等待。触发时等候上限为 0.35 秒，备用未就绪继续安全拒绝。几何、惯性、检测和长窗拒绝门限继续沿用。异步版相较同步版，六组里有五组 p95 延迟下降，改善范围 6.22–11.37 秒。剩余一组增加 0.26 秒。

## 故障拒绝时的第二项修复

较早的有故障实验有六次候选退出码为 −9。拒绝时控制器同步等待候选退出，输入进程通过 fork 继承了候选的标准输入写端，导致它无法及时收到 EOF。在保持输入源运行的控制实验中，fork 组的替代工作进程在 0.8 秒内无法读到 EOF；spawn 组能正常退出。已改为独立 spawn 启动输入源，并在后台收尾候选。

修复后另跑三个短长组，每组用同一最新版、同样输入和调度做原生及插件对照。六个实验臂均完成，插件的候选退出码全部为 0。V2_02 的短事件拒绝仍成立，本次观测停发从先前异步实验的 11.130 秒降到 3.318 秒。两次运行的宿主调度不同，数值差包含运行波动；EOF 控制实验直接验证了句柄原因。

| 最新版回归 | 原生／插件及时可用帧 | 原生／插件订阅延迟 p95 | 恢复结果 |
| --- | ---: | ---: | --- |
| V1_01 短长 | 0／0 | 1.33／3.37 s | 短窗检查点不同拒绝，第二次缺可用备用仍拒绝 |
| V2_01 短长 | 95／102 | 4.65／5.27 s | 短窗 7/7 外部确认，长窗安全拒绝 |
| V2_02 短长 | 33／12 | 9.99／14.05 s | 两次安全拒绝 |

这组三轮结果支持两项具体改进：异步镜像降低了相对同步版的排队，隔离句柄和后台收尾消除了回归中的候选强制终止。矩阵中各插件版本与原生的 **19 个比较均未过线**。V2_01 最新版多了 7 条及时可用位姿，同时多了 0.62 秒 p95 延迟，超过预先固定的 0.25 秒条件。保持原生速度时获得稳定的备用状态、以及拒绝后重建可验证备用，仍是本矩阵定位的工程缺口。

## 复现

逐臂版本、CPU 集合、实际外部回执校验、相同输入校验、退出状态、共同位置 RMSE、停发、接回延迟与 SHA 均见结构化结果。每个条件内使用同一 CPU 集合，多组同时运行于不同 CPU 集合。采集之间不直接比较墙钟速度。最新修复在已经看过的三个录制上复验，该轮是回归，对修复后的完整版本仍缺新的独立留出采集。
