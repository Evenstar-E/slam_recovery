# 验收 bbc3dcb：FAST-LIVO2 收口与独立验证的新缺陷

范围：9b58bd5、2430ff9、bbc3dcb。面向远端开发侧，2026-11-09。

## 总结

FAST-LIVO2 的新结果与转换路径修复可以接受；撤回不可靠仿真结论是正确做法。但 2430ff9 的节点逻辑尚不能通过安全验收：候选依赖的支持筛选会跳过坏帧，然后把它们与好帧一起提交。独立参考的原始拼接缺陷已删除，不代表独立验收整体完成。

本机 unittest **27/27 PASS**。另实际运行本目录 probe.py，复现两个缺陷。未播 bag、未重跑 FAST-LIVO2 或完整 S1/S2；运行数字来自归档。PDF 正文未独立核验。

## 已通过的改进

- 9b58bd5：注入距离参数显式化并默认 4.30 m；补上退化条件视觉开/关。room_02 ATE 0.0771→1.0313（开）/1.0481（关）；hall_01 0.3143→4.2331（开）/4.1820（关）。可报告该注入条件下显著失效，不可据异序列结果排序宿主鲁棒性。

## 阻断项 P1：跳过未支持帧，却提交整个候选

位置：transaction_manager_node.py:304（配对筛选）、:402（holdout 筛选）、:445（完整 repaired_poses 进入 CandidateMap）。

支持率由候选位姿决定。坏位姿把扫描移出参考覆盖后，该帧从配对与 holdout 中消失；只要剩余帧达数量门限，就仍能通过。提交集合没有同步限制。

已实际复现：600 点 z=0 平面参考，20 帧候选，前 8 帧正确、后 12 帧平移至 z=100 m；incumbent 为 z=0.3 m。提供显式独立辅助信息矩阵 100I，仅用于让其他门限通过，未修改评分函数。结果：

```

holdout_nis: 0.0
num_paired_frames: 8
frames_without_independent_reference: 12
wilson_lower_bound: 0.7472427908584185
holdout_frames_total: 4
holdout_frames_scorable: 2
committed_poses: 20
committed_100m_poses: 12
```

这是入口级真实提交反例，不是只调用 Wilson 的抽象测试。支持缺失应阻止完整候选提交，或明确拆分成独立验证的可提交子集，其余帧仍隔离，并重新验证边界与图依赖。不能把“坏位姿导致不支持”一律当作中性的无证据，也不能通过放宽 NIS 来解决。

## 其他代码缺陷

### P2：参考扫描 ID 排除没有实际来源

节点 :397 把 reference_keys 无条件设为空；_measure_paired_evidence :293-297 虽支持排除，但入口没有导出参考体素/点云所属关键帧。若修复集合包含已可信锚帧，这些帧可能对自己的地图评分。冻结参考应携带扫描来源，评分集合必须与参考构建集合去重。不能仅靠注释声称已保证独立。

### P2：缺失扫描抛 KeyError

:402 在扫描存在性检查前调用 _frame_has_reference_support；helper :235 直接索引 scan_buffer_body。非空参考加 repaired_poses={0:I}、缺扫描 0 时，实际抛 KeyError: 0。应按缺测返回 MISSING/等待，而不是崩溃；同时纳入候选完整覆盖检查。

## 仿真 validity 的实现还需修正

以下不改变当前归档 FAILED 的方向，但会使未来通过判决不可信：

1. :372 在 evaluate_and_commit_candidate 之后读取参考；若未来候选通过，参考已被其提交修改。应在评估前快照独立参考。
2. :377 用 repaired poses 判 GT 帧支持，而 :379 才用 GT 投影；GT 检查的选样因此受候选误差控制。应按 GT 定义支持并单独报告候选支持差异。
3. :374-384 取所有支持帧的 median；门控是每五帧 holdout 的 mean。两者不同，不能声称复现同一个准入统计。记录相同扫描 ID 与相同聚合。
4. :470 空 val_8nn 返回 PASSED，NaN 比较也可落入 PASSED；跨场景平均还能掩盖单场景失败。每个预期场景需非空、有限证据并逐场景判断；缺测应 MISSING/INVALID。
5. :386-395 的密度扫描仍被 NIS 函数截到最多 600 参考点；20000/200000 还可能返回同一底层集合。因此不能排除局部拟合稀疏度/邻域结构的影响。

归档自身也反驳“密度增加没有变化”的字面说法：1500 cap 的第二场景是 26.498，20000 cap 为 14.770；后两档相同不等于密度影响被排除。应扫实际估计器预算，记录实际点数、邻域半径、平面质量及跨平面混合情况，避免直接归因“全部是法向错误”。

## 论文与实验记录建议

- 保留不利结果、明确撤回旧仿真通过声明，不通过提高阈值恢复 Mode 2。
- FAST-LIVO2 的视觉开/关是当前配置下的测量，不代表所有 LIVO 的视觉贡献；findings 仍有一句“Why the photometric term is inert”应改成“why aggregate ATE changes little”。
- 0.35 m 下双模态窗口差异不能直接作为 4.30 m 下视觉机理的证据；分别标注条件。
- 尚无 FAST-LIVO2 B6 修复结果，新宿主目前证明失效条件，不证明模块恢复价值。
- 仿真撤回后，真实归档的接受/拒绝案例仍可报告，但不是宿主完整地图闭环验收，相关性与局部平面尺度须审视。
- conversion sidecar 机制已加，但新运行的输入 hash、调用参数、真实注入计数及版本应归档，机制存在不等于历史运行已可重现。
