## 0. 链路的可验证性（先过这关，否则后面的数都不算）

重算用的是与节点**同一套预处理**（消息点、去非有限、按 `SCAN_CAP=6000` 步长抽样），
`sigma_meas_m=0.075`，取 `vᵀΛv`（在 body 基，与 `transport_information` 后的二次型相同）。

| 触发类 | 运行 | 触发帧戳 | 匹配 bag 帧 Δ | 重算 `weak_dir_info` | 运行记录值 | 是否复现 |
|---|---|---|---:|---:|---:|---|
| 启动早期 | `030656Z_2938083` | 1627643742844584942 | −23.19 ms | **40.2316** | 40.23159328113725 | **是** |
| 注入 onset | `044830Z_3036955` | 1627643759659727812 | −5.50 ms | **1.1019** | 1.101917196050157 | **是** |

两类的相对误差都在 1e-4 量级。**"bag 扫描 → 门里的数"这条链是复现出来的，不是假设的。**
触发帧戳是**位姿**戳，与扫描戳相差 5–23 ms，所以匹配窗口用活循环自己的 40 ms 配对窗。

## 1. 两类触发帧的几何（节点实际看到的 6000 点云）

| | 启动早期 | 注入 onset | 比值 |
|---|---:|---:|---:|
| 点云 | 6000 | 6000 | — |
| `weak_dir_info` = `vᵀΛv` | **40.232** | **1.102** | **36.5×** |
| `min_eig_trans` | 40.232 | 1.102 | 36.5× |
| `min_eig_rot` | 171.27 | 5.282 | 32.4× |
| 6×6 FIM 最小特征值 | 35.12 | 1.1019 | 31.9× |
| 6×6 FIM 最大特征值 | 1190.1 | 449.5 | 2.6× |
| `‖cov‖₂` | 0.028 | 0.908 | 32.4× |

两个结构性事实：

1. **`weak_dir_info` 恒等于 `min_eig_trans`**（40.232/40.232、1.102/1.102），
   而 onset 那一帧的 `weak_dir_info` 又等于 6×6 FIM 的最小特征值。
   也就是说门在比的是**最小平移特征值**，不是某个"综合信息量"。
2. 两类的差距在**弱方向上 36 倍**，但在最强方向上只有 2.6 倍——
   差别不是"扫描点多寡"，是**几何在弱方向上是否退化**。

## 2. 参考分辨率下的信息量（voxel 抽样，与参考同一规则）

参考本身是空间抽样的（ICP 搜索 0.5 m 体素、`support_reference` 0.3 m 体素）。

| 抽样 | 启动早期 点数 / info | 注入 onset 点数 / info |
|---|---|---|
| 节点 6000 点 | 6000 / 40.23 | 6000 / 1.102 |
| 1.0 m 体素 | 280 / 30.86 | **12** / **0.0010** |
| 0.5 m 体素 | 753 / 53.05 | **48** / **1.342** |
| 0.3 m 体素 | 1341 / 40.82 | **107** / **3.088** |

两点必须照实说：

- onset 那帧在参考分辨率下**只剩 12–107 个点**，1.0 m 体素下 info 掉到 0.001（几何消失）；
- 但 0.3 m 体素下 info 反而从 1.102 升到 **3.088**——因为节点那 6000 点是**等步长**抽样，
  空间上高度冗余，而 voxel 抽样取的是空间上互异的点，对平面拟合更有约束。
  **所以"点少 → 信息少"在这套管线下不成立**，这是实测反例，不能靠直觉推。

## 3. 参考分辨率 → `tau_abs_min` 的测出来的边界

- onset 这一类触发帧，在**参考自身的分辨率（0.3 m）**下携带 **3.088**；
- 早启动那一类在同样分辨率下携带 **40.82**；
- 两趟候选的 `info_after` 分别是 4.62–4.70（host_poses）与 4.03–4.47（ICP）。

所以 `tau_abs_min` 若设为 **> 3.09**，就把 onset 这一类几何**整类排除**；
若设在 3.09 以下，两类都能被"绝对下限"这一关放行，区分只能靠比值 `kappa`。

**这是测出来的边界，不是建议值。** 建议值由预注册冻结，不在这份文件里。

## 4. 把 FIM 的 σ 对齐到实测残差（**缩放值，非测量值**）

`compute_6dof_point_to_plane_fim` 用 `sigma=0.075`，而 ICP 的实测残差下限是 3.8 cm（线上）
与 4–5 cm（离线）。信息量 ∝ 1/σ²，按实测残差重标：

| 假设的 FIM σ | 早启动（节点/0.3 m） | onset（节点/0.3 m） |
|---|---|---|
| 0.075 m（现行） | 40.23 / 40.82 | 1.102 / 3.088 |
| 0.050 m（5.0 cm 残差） | 90.5 / 91.8 | 2.48 / 6.95 |
| 0.045 m（4.5 cm 残差） | 111.8 / 113.4 | 3.06 / 8.58 |
| 0.038 m（3.8 cm 残差） | 156.7 / 159.0 | 4.29 / 12.03 |

**这些是缩放，不是重新测量**；标出来是为了说明：即使把 σ 压到实测残差，onset 这一类在
节点分辨率下也只到 2.5–4.3，仍远低于 25。**换 σ 救不了绝对阈值。**

## 5. 取不到的量

  只在 `HealthWindow` 里存在，**16 趟运行一次都没落盘**（已在 `tau_info_scale_evidence.md` 记录）；

## 6. 这份文件支持什么、不支持什么

支持：
- 触发帧几何 → 弱方向信息量的对应关系，两类都复现到 1e-4；
- `tau_abs_min` 的一个**测出来的**边界（3.088，onset 类在参考分辨率下的信息量）；
- "点更少不等于信息更少"的反例（1.102 → 3.088）。

不支持：
- 任何 `kappa` 的具体取值（那是预注册要冻结的，需要确认性运行）；
- 任何"应该改成多少"的结论——本文件不提出改动。
