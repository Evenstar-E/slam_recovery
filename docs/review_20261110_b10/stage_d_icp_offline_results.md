## 1. 冻结参数（§9）与两项实现常数

§9 冻结：初值=宿主位姿、参考 30 m 内上限 20,000、扫描抽样 2,000、对应门 0.5→0.25 m、
迭代上限 20、收敛 `‖Δξ‖<1e-6`。**未改任何一项。**

两项是我选的实现常数，不属于 §9，已写进结果的 `config`：

- **邻域搜索体素 0.5 m**（第一版用 1.0 m，在密集表面上每格数百点，2000 查询 ×27 格 ×N 让单帧
  超过 3 s、全量 19 分钟跑不完）；
- **每格最多取 64 点**（只在极密格生效；生效时最近邻取自这个上限而不是整格，已在 config 里声明）。

## 2. 结果：399 帧全部产出候选

| 总体 | 值 |
|---|---|
| 帧数 | 399 / 399 产出候选 |
| 耗时 | 1066 s，2.67 s/帧 |
| CONVERGED | **53（13%）** |
| ITERATION_LIMIT | **346** |
| 终点残差（全部） | 中位 4.98 cm，p90 5.88 cm，max 7.09 cm |
| 位移（全部） | 中位 **47.77 cm**，p90 54.39 cm，max 307.67 cm |
| 旋转变化 | 中位 0.78°，p90 2.31°，p99 21.22°，max 28.16° |

### 2.1 converged 与 iteration_limit 的残差**不可分**

| 类别 | n | 残差中位 | p90 |
|---|---|---|---|
| CONVERGED | 53 | 4.70 cm | 5.54 cm |
| ITERATION_LIMIT | 346 | 5.06 cm | 5.93 cm |

控制组同一现象：CONVERGED 4.12 cm、ITERATION_LIMIT 4.12 cm，**完全相同**。

所以在这套参考下，**"收敛"不携带任何质量信息**：残差落在 4–5 cm 的下限上，那是参考点密度
（20k 点、0.5 m 体素）加 8-NN 法向估计的分辨率下限，不是迭代是否收敛的残差。报告里两个类别
分开计数、分开给分布，但不把 `converged=True` 读成"更好"。

### 2.2 控制组：已经一致的帧几乎不动

控制组取 onset 前最后 10 帧，参考**排除这 10 帧**（自己不能给自己当参考）：

| | 位移中位 | 位移 p90 | 残差中位 |
|---|---|---|---|
| 控制（宿主位姿本已一致） | **1.75 cm** | 3.00 cm | 4.12 cm |
| 隔离段（污染帧） | **47.77 cm** | 54.39 cm | 4.98 cm |

**27 倍分离**，说明重配准是在对污染作出反应，不是无差别漂移。

### 2.3 但位移 ≠ 改进

这是本节最重要的一句：**48 cm 是"移动了多少"，不是"向真值靠近了多少"。**
过滤后那一趟没有 GT 位姿，所以不能说 48 cm 让候选更准。要做这个判断，必须
拿独立标签（GT 或干净运行 proxy）去评，那是 B10 的事，不是这一节的。

尾部同样 `UNCONFIRMED`：

| 位移阈值 | 帧数 |
|---|---|
| > 0.5 m | 92 |
| > 1.0 m | 15 |
| > 2.0 m | 8 |
| > 3.0 m | 2 |

旋转 p99 是 21.2°。这些要么是宿主位姿真的大幅偏离、要么是 ICP 吸到了错误的局部极小，
**没有 GT 无法区分**，不写成"ICP 修好了大误差"。

## 3. 这不能回答什么

- **不能**说明实时链路能产出候选流：活循环的候选流仍受"决策侧证据腿"与 `tau_info` 量级问题限制；
- **不能**说明候选应该被提交：那是门的决定；
- **不能**说明 ICP 提升了精度：控制组只证明它不漂移，隔离段的位移没有独立标签；
- **没有**接进 `candidates.jsonl`：那需要把 `IcpResult.as_dict()` 的
  `icp_iterations / icp_residual / icp_converged / icp_inliers` 接到活循环里，
  并以 `candidate_source="icp_reregistration"` 单独归档——本趟只做了离线构造。



## 5. 接入活循环：改成"整段一次刚体 ICP"

逐帧 ICP 在决策点不可行（实测 13 s/帧，23 帧约 5 min；30 s 预算下只做出 3/23，
`min_paired_observations=4` 都不到，拒绝理由是证据缺失）。按 S1 的裁决改成
**对隔离段做一次刚体 ICP**，把求得的修正 `ΔT` 作用到全部候选位姿上。

没有改任何 §9 参数。**扫描抽样一直是 2,000**——之前日志里打印的 `[6000]` 是节点
`scan_buffer_body` 的缓冲尺寸（`SCAN_CAP`），不是 ICP 的抽样；`IcpResult.scan_points`
每一帧都记录为 2000。日志已改成打印 "buffer scan sizes"，避免再被误读。

实测（receipt `/tmp/fl_native_20261110T051744Z_3059939`，load 51）：

| 项 | 值 |
|---|---|
| ICP 次数 | **1**（整段） |
| 耗时 | **11.8 s** |
| 扫描点 / 参考点 | 2000 / 19,039 |
| 迭代 | 20（`ITERATION_LIMIT`，未进 1e-6） |
| 残差 | 3.81 cm |
| 内点 | 2000 / 2000 |
| 修正量 | 平移 **0.459 m**，旋转 **3.73°** |
| 候选帧 | **25 / 25 全部产出** |
| 配对证据 | **PASSED**，Wilson **0.9023**（25/25 帧改善） |
| 拒绝理由 | `Insufficient verified info`（`weak_dir_info_after = 4.470 < 25`） |

**结论**：(d) 在决策点**可行**，但 11.8 s 是 2 s 确认边距的约 6 倍，所以决策是延迟的。
证据腿与候选来源无关地通过了，Mode 3 由信息腿决定——与 S1 的预判一致。

`ITERATION_LIMIT` 而不是 `CONVERGED` 与离线一致：1e-6 的判据在这套参考下达不到，
残差停在参考分辨率的下限（离线 4–5 cm，线上 3.8 cm）。
