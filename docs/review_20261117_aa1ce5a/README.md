## 1. “本宿主+本序列accepted不可达”的口径

**判定：阻断该扩大表述进入文档/论文；不阻断option③按预注册停止新run。**

必须收窄为：

> **在当前FAST-LIO派生宿主、已试候选生成器、已试窗口及冻结协议下，未获得accepted测量修复提交。现有证据不支持对宿主+序列作一般“不可达”判断。**

理由：

- 多个run确实没有accepted，但失败原因包括候选未收敛、初值接线、checkpoint边界和候选生成失败，不能全部归为信息不可恢复。
- v9j E1是`TOO_FEW_INLIERS`后退回incumbent，候选与基线相同；它无法回答“静止窗+注入是否可改善”，不能作为一般不可达的证据。
- v9i属于另一输入序列，且只证明host_poses相对常速incumbent的paired-benefit，不是accepted修复链。
- 现有run数量不是穷尽候选方法、事件和独立标签的证明。

因此option③可以表示“当前实现/协议下停止追求accepted并收口”，不能写成“科学上不可能修复”。

## 2. “0.5m连续性与真实运动互斥”能否作为结构性结论

**判定：不能；该表述被当前源码和run原件直接否定。**

当前`core.py`的重入规则是：

- `reentry_elapsed_s is None`时，才使用裸`0.5m`；
- 有时间信息时，判据是 **`jump <= 0.5 + 2.0 × elapsed_s`**。

已审核原件：

| run／事件 | 重入距离 | 时间包络 | 结论 |
|---|---:|---:|---|
| v9i E1 | 4.089475m | 8.899303m（Δt=4.199651s） | **PASS，不是被重入拒绝** |
| v9i E2 | 74.664804m | 31.300203m（Δt=15.400101s） | FAIL |
| v9j E1 | 1.074037m | 8.701896m（Δt=4.100948s） | **PASS** |
| v9j E2 | 0.071129m | 8.899341m（Δt=4.199671s） | **PASS** |

v9i E1还同时失败信息增益和holdout；v9j两事件信息增益通过，但Wilson和holdout失败，E2 checkpoint另晚边界。因此不能把“真实运动必然超过0.5m”当作统一结构矛盾，更不能说它是当前唯一断点。

若论文需要一般推导，必须写明**实际Δt、候选首帧与锚点定义、速度/加速度假设及不确定性**，不能仅用`速度×隔离时长 > 0.5m`替代当前门的时间包络。无需为此新增run。

## 4. v9j失败退回incumbent属于什么缺陷，是否补测试/重跑

**判定：候选生成器实现缺陷，不是门阈值结论。option③收口不重跑；未来若重新评价候选方法，修复前不得把它当确认run。**

源码`_icp_core._fail`返回`pose=init`，整段刚体路径随后仍把这些位姿组成候选，导致失败时candidate=incumbent、收益恒为0。这掩盖了“没有成功生成候选”和“成功生成但无改善”的区别。

最低处理：

1. 增加**一条**针对当前缺陷的回归语义：`TOO_FEW_INLIERS / TOO_FEW_CORRESPONDENCES / LOST_CORRESPONDENCES`必须输出“无候选/明确失败”，不得以初值克隆进入有效候选人口。无需扩展异常矩阵或重写ICP。
2. v9j现有负结果保留，**不需要为了证明该实现缺陷而重跑**；其E1不得用于推断静止窗没有可改善量。
3. 若未来用户重新授权评价该候选方法，应先修失败语义并做一次有界复验；该复验需要新的用户授权，不由本审阅发起。
