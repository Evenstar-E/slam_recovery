## 10. 600 点预算为什么会阻塞验收（补充技术解释）

`validation/fim_and_holdout.py:127-138` 对整张参考地图按数组顺序抽样，最多留 600 点；查询扫描最多留 300 点，再对每个查询找约 8 个近邻拟合平面。这里的 600 是计算预算，不是传感器数据量，也不是足够几何支持的证明。

主要问题是“全局裁掉证据，再做局部邻域查询”：地图越大，每个待验证点附近可能越缺真实邻居，近邻会跨墙角、跨表面或来自远处。正确候选也可能出现大点面残差而被拒；偶然拟合有利平面也可能低估错误，不能把它仅理解成保守机制。

外层给 1500/20000/200000 点后仍有内部 600 cap，所以增加外层预算不等于增加局部拟合支持。不同外层集合会改变抽到的 600 点，数值仍可改变；不得声称密度无影响或全部误差已确定来自 cap。

本次空间采样修复用于覆盖判定，评分仍受内部 cap 影响：可能“地图确实覆盖该帧”，却在评分时丢掉附近点。它阻塞的是验证/准入，不是候选修复本身。

建议的修复协议（不是直接把 600 改成 60000）：

1. 保持有限且空间分布合理的查询点预算；在完整或空间降采样参考上建立局部近邻索引。
2. 每个查询限制邻域半径并要求最小点数；检查平面质量、跨表面混合和法向不确定度。
3. 无合格邻域记缺证据，不把远处平面外推当作评分。缺证据点/帧不得随有效子集进入提交。
4. 在独立健康校准区间确定经验残差尺度，在不同留出区间测健康误拒、坏候选误收和计算时延。
5. 新 estimator 改变所有历史分数，应版本化协议、保留旧档并重跑关键正负候选；不为保住旧数冻结已知错误。

验收至少需报告：实际参考/查询数、邻域半径与有效点比例、平面质量分布、噪声尺度来源、GT/健康候选和错误候选的结果，以及 P50/P99 用时。先修坐标系与输入配对，再比较预算，否则预算敏感性本身也会被混杂。
