## 2. 三个选项

### A. 维持现状 + 只保留诊断

- 内容：支持谓词、检测决定不变；availability 日志与 predicted-pose 字段只做记录。
- 成本：0；已实现、已归档。
- 作用：保留可追溯性，不改行为。
- 局限：支持条件仍是普遍前置门槛；147 帧"预测可恢复"的帧仍不会进检测器；根因仍 UNKNOWN。
- 风险：低。

### B. 双位姿仅作诊断分级（当前已实现，可继续收窄判读）

- 内容：保留 `support_under_predicted_pose`，把 UNAVAILABLE 细分为"短时预测解释不了"
  （both_low）与"宿主位姿可疑"（only_host_low），但仍**不进入检测决定**。
- 成本：0（已实现）；判读规则已在状态 §90/§91 收窄（both_low 不能宣布覆盖不足是唯一原因）。
- 作用：给用户/S3 一个可复核的分级，不改变任何决定。
- 局限：不解除任何帧的不可用；预测位姿本身依赖 trusted 地图，有自参考风险（472–517 的
  predicted_lower 就是反例）。
- 风险：低（只读）。

### C. 让支持判定显式区分"位姿可疑"与"地图不覆盖"

- 内容：在 `available` 判定里引入第三个状态（例如 `POSE_SUSPECT`）：宿主位姿支持不过但预测
  位姿过时，该帧**不送检测器**但仍标注为位姿可疑，而不是与地图不覆盖混为一谈；或者允许检测器
  在该帧用预测位姿评估（更强的改动）。
- 成本：中；改动 `available` 的语义、日志、可能影响检测人口与计数；需要重跑对照。
- 作用：把 147 帧从"无证据"中分离出来，为后续是否允许其进入检测提供依据。
- 风险：**预测位姿来自 trusted 地图的常速外推**，用它做支持会引入自参考；472–517 显示预测
  可以比宿主更差；一旦进入决定，等于改变检测策略，必须用户批准。
- 前置：需要一个独立位姿/轨迹参考来判定"位姿可疑"是否真的是漂移，而不只是支持谓词的失败。

## 3. 三个结构方向（超出本轮范围，仅列方向）

1. **位姿相对支持（pose-relative support）**：把 1 m 硬半径改为"相对预测轨迹 + 显式位姿误差
   项"的支持度量；需要位姿不确定度模型，改动支持谓词与检测人口。证据支持：147 帧预测恢复；
   反例：54 帧预测更差。
2. **参考覆盖管理（reference coverage）**：两套位姿都低的 191 帧，问题在参考地图对扫描的覆盖，
   而不是位姿；方向是空间采样/子图激活/地图密度，而不是放宽支持阈值。风险与成本最高，且
   不在当前冻结范围内。
3. **把可用性与检测拆开（availability vs detection）**：显式区分"无独立证据"与"检测器判健康/
   故障"，让不可用帧有自己的策略（等待、补参考、或明确不判），而不是用一个布尔同时承担两件事。
   这是语义/设计改动，不改变阈值；与现状的 `DISABLED`/`UNAVAILABLE` 区分一致。

## 4. 仍为 UNKNOWN

- 191 帧两套都低的**根因**（地图覆盖、几何退化、位姿历史）——分解只能排除"短时预测可解释"，
  不能证明覆盖不足是唯一原因（状态 §91 已收窄）。
- 147 帧预测恢复是否真是位姿漂移——没有独立轨迹/真值，只有支持谓词的两种初始化。
- 54 帧预测更差的原因（trusted 外推失效？位姿跳变？）——UNKNOWN。
- availability 的 run 间差异（402 vs 544 行、同戳窗口状态不同）如何影响任何 C 方案的对照。

## 5. 建议（供用户/S3 选择，不自行执行）

- 诊断按用户决定暂停；不再加日志字段或跑诊断轮次。
- 若恢复，先回答"147 帧是否真为位姿漂移"（需要独立参考），再决定 C 是否值得做；A/B 可立即
  作为现状保留。
- 任何进入检测决定的改动（C 或结构方向 2）都需要用户明确批准，并重跑同输入对照。
