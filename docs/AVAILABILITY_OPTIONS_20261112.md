## 4. 结构层面的三个方向（不是诊断，是要不要改系统）

1. **保持现状**：支持谓词作为硬前置，UNAVAILABLE 时继续 ingesting 但不检测——在线链的上游断点保持，E2 无法自愈。
2. **参考刷新**：允许隔离期间参考按可信位姿更新（或使用 restore 前快照做支持），代价是参考不再"独立于候选"这一性质需要重新声明。
3. **门结构变更**：把"是否支持"从硬前置改为证据等级（例如低支持时降级判决而非直接不判），属检测/门方法变更，必须按项目规则先做有限比较、由用户选。

## 5. 结论与请求

当前证据足以说明 UNAVAILABLE 的**位置**（支持谓词解释了全部 4128 帧的判决来源）与**分支规模**（比例不足分支：旧归档 2472/4128≈60%，本次诊断 run 285/307≈92.8%；其余为空参考；跨 run 变化大），
不足以说明**根因**。若继续：建议只做 B（诊断、不改系统）；若转向：回原生主线（后缀 catch-up / E2）。
**任何门/阈值/检测策略改动都不在本页实施，等用户明确选择。**
