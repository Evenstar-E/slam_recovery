## 4. 本次暴露并已修的一个缺陷：检查点 stamp 晚 100 ms

两次的 `checkpoint_check.status = LATE_AFTER_BOUNDARY`，都恰好晚 **0.10019 s**。
原因在接线本身：延迟命令在**即将处理的那一帧**入口处执行，快照内容确实是「上一帧处理完的状态」
（在边界之前），但记录的时间戳用了**到达帧**的 stamp。修正为记录 `nr_last_proc_time`
（最后一帧已处理完的时间），并把延迟命令的检查移到 `mappingProcessInterval` 分支内部。
重建后二进制 sha `e9373b30…`。

**该修正尚未在 run 中复验**——本次报告的所有数字来自修正前的二进制 `f7733000…`。
