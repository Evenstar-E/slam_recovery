## 4. 本次暴露的协议缺陷（如实记，影响可复现性）

1. **检查点晚于越界点**：两事件的 `checkpoint_check.status` 均为 `LATE_AFTER_BOUNDARY`——
   E1 快照 stamp 比越界点晚 0.22 s，E2 晚 **9.71 s**；`rollback_support` 记为
   `UNSUPPORTED_AT_OR_BEFORE_QSTART`。即「回滚到污染前」在两次事件上都**没有得到满足**。
2. **driver 落后导致事件 2 触发晚**：声明 E2 为 bag 230.09 s，实际在 **256.50 s** 才触发（晚 26.41 s）；
   E1 基本准时（115.50 s vs 115.99 s）。原因是 driver 处理速率低于宿主发布速率（`pose_callback`
   p95 207 ms、`scan_callback` p95 558 ms），回放逐步积压；`max_backlog_messages=429`。
3. **宿主自己的地图重建没有被恢复层挡住**：E1 快照 `map_points=221046`，E2 快照只有 **3873**；
   事件间宿主多次 `construct a new map` / `publish hibernating map operation`，全程 152 次
   `IMU Initial Done`，其中 50 次落在 E1 窗口（120–150 s）、85 次落在 E2 窗口（240–270 s）。
   恢复层 `restore` 的 ack 有效，但**宿主随后的原生重建把地图换掉了**。本次没有「不做 hold」的基线 run，
   不能把这些重启归因于接线本身。
4. **配对率**：3070/4212 位姿与 3070/3553 扫描配对（窗口 40 ms）；离线臂用 20 ms，二者**不可共表**。
