## 3. 降速带来的两个新失败（必须记）

### 3.1 后端 alaserPGO 在 E1 之后崩溃

`alaserPGO` 于 **12:45:52**（E1 resume 12:44:59 之后 53 s、E2 hold 12:48:32 之前 2 分 40 秒）以
**exit -6（SIGABRT）** 退出：

```
alaserPGO: .../KDTreeVectorOfVectorsAdaptor.h:61: ... Assertion `mat.size() != 0 && mat[0].size() != 0' failed.
```

即 ScanContext 的 KD 树适配器收到空描述子矩阵。ROS launch 记录 `all processes on machine have died`。
后果：**整个第二事件没有后端**——`pgo.log` 只有 E1 的 `frozen`/`released` 一对，
E2 的冻结从未发生；PGO 侧尾段证据为零。

**归因状态：未定**。同一份源码与二进制在 v1（1.0×）跑完 469 s 未崩；v2 崩在 E1 resume 后的
「sleep active map / start a new active map」路径附近。可能是宿主原生的空描述子竞争，
也可能是本次冻结在释放时机上与地图切换交错。**未复现、未定位，不能算到接线头上，也不能排除。**

### 3.2 driver 提前终止，尾段丢失

宿主在 E2 后进入 14.0 s（bag 时间）的休眠闸口；0.5× 下等于 **28 s 墙钟**，超过 driver 的
`--pose-stale-sec 15`，12:49:23 以 `INPUT_STALE` 终止（最后一次位姿是 bag 243.0 s）。回放继续到
12:56:40（bag 469 s），**最后约 213 s bag 没有 driver**，因此第二事件之后的尾段不存在。

这正是预登记 §3 声明的 wall/bag 换算副作用：`pose_stale`、`wait_limit`、`arm_lead` 都是墙钟量，
降速等于把它们在 bag 时间上放大一倍。v1 里 14 s 的休眠闸口恰好小于 15 s 墙钟，v2 里就超过了。

**与 v1 的对照必须写清楚**：v1 的两次 paired 都是 PASS（12/13 Wilson 0.718；21/21 Wilson 0.886），

**这只说明二者同时变化，不足以判定因果**——不能据此写「v1 的配对收益是晚检查点造成的假象」，
也不能写「修正检查点必然毁掉配对收益」。要分离需要专门实验。
