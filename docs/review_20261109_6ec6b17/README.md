## 二、为什么 FAST-LIVO2 几乎不受影响

### 2.1 先纠正：不是"完全不受影响"

| 运行 | ATE | 窗口 RMSE [20,40] s |
|---|---|---|
| clean，视觉开 | 0.0771 | 0.1077 |
| clean，仅 LiDAR-惯性 | 0.0761 | 0.1063 |
| 88% 遮挡，视觉开 | **0.0886**（+15%） | **0.1287**（+19.5%） |

对比 LiDAR 宿主在同类 88% 注入下的表现（FAST-LIO2 0.1316 → 1.2996，MM-LINS 0.3458 → 5.2635），差距是**两个数量级**。所以"几乎不受影响"成立，"完全不受影响"不成立。

### 2.2 视觉项是惰性的——这是实测，不是推测

clean 上带视觉 0.0771，去掉视觉 0.0761。**去掉视觉反而略好。** 说明在这一段序列上视觉残差几乎没有贡献。

可能原因（无法从 manifest 区分）：
- `img_point_cov: 100` 相对 LiDAR 的 `dept_err: 0.02` / `beam_err: 0.05` 权重极低；
- room_02 室内纹理不足以提供稳定光度约束；
- 相机-雷达外参/时间同步未充分标定，视觉残差被当作异常值忽略。

**直接后果：这一跑实际上是 LIO 跑，不是 LIVO 跑。** 因此"多模态让它免疫"这个解释不成立，manifest 的 finding #2 也承认了这一点。

### 2.3 LiDAR-惯性为什么撑得住——四个候选机制（按可信度排序）

1. **注入几何比 LiDAR 宿主那组温和得多。**
   `prepare_m2dgr_for_fastlivo.py` 调用注入器时**没有传 `bag_distance_m`**，于是用默认 **0.35 m**（manifest 也记为 0.35）。而 `generate_hall01_injected_bags.py` 用的是 **4.30 m**。
   0.35 m 的薄板落在近场保护带边缘（`blind` 虽已降到 0.3，但多数 LIO 对 ≤1 m 的点有额外处理）；4.30 m 的薄板看起来就是一面正常的墙，**欺骗性强得多**。
   → 这单独一条就足以解释大部分差异。

2. **体固定薄板在体素地图里"自我抹平"。**
   薄板固定在雷达坐标系，机器人一动，它就在世界系里扫过，扫过的每个体素只得到少量点，达不到 `layer_init_num: [5,5,5,5,5]`，平面拟合不稳定（`min_eigen_value: 0.0025`）。**近场体固定薄板对体素地图型 LIO 是自我消除的**，而单扫描强耦合的 IEKF 更容易被拖走。

3. **IMU 撑住了 20 s。** 室内慢速、`acc_cov 0.5`/`gyr_cov 0.3`，20 s 内漂 0.13 m 与纯 IMU 递推 + 弱 LiDAR 修正的量级一致。

4. **12% 存活扇区仍有墙和角点。** room_02 是小房间，遮挡没有把几何彻底抹掉。

### 2.4 这次实验的硬缺口：缺 `degraded + img_en=0`

现有三臂是：

```
clean + 视觉开
clean + 视觉关
degraded + 视觉开      ← 缺 degraded + 视觉关
```

**没有第四臂，就无法区分"视觉救了它"和"LIO 自己撑住了"。** manifest 用 clean 上的 noimg 去推断后者，这个推断不成立：视觉的贡献在 clean 和 degraded 下本就可以不同，而那正是要检验的假设。

### 2.5 manifest 无法证明注入确实发生了

`prepare_m2dgr_for_fastlivo.py` 只有在**同时给出** `--inject-start-rel` 与 `--inject-end-rel` 时才注入，并会打印 `injected` 帧数。但 `p11_fastlivo2_fifth_host_benchmark.json` 的 `conversion` 块只记了 images/clouds/IMU 数量，**没有 inject 窗口、没有 injected 帧数**。

因此这份记录**无法区分"注入但无害"与"根本没注入"**。这是本轮最需要补的一个字段。

### 2.6 跨宿主不可比

| | LiDAR 宿主实验 | FAST-LIVO2 实验 |
|---|---|---|
| 薄板距离 | 4.30 m | **0.35 m** |
| 序列 | street_08 / room_dark_02 | room_02 |
| 窗口 | 20 s | 20 s（总长 60 s，ATE 被 clean 段稀释） |

在这三处不同之下，说"FAST-LIVO2 比其他宿主鲁棒"是不成立的。

## 三、能直接回答这个问题的三条低成本诊断

1. **补第四臂 `degraded + img_en=0`。** 只多跑一次，就能把"视觉是否补偿"变成可测命题。
2. **打开 `pub_effect_point_en: true`，统计 [20,40] s 内每帧实际参与优化的点数。** 若有效点塌缩到约 12%，机制 2（体素地图拒绝）被证实；若仍接近 100%，说明薄板被接受了却没能拖动状态，需另找原因。这是最直接的一条证据。
3. **把注入距离对齐到 4.30 m 再跑一次。** 若此时 ATE 显著恶化，说明"免疫"主要来自注入几何太温和，而不是模态。

## 四、给论文的建议

- 把这一跑写成**阴性对照**而不是"第五宿主的正面结果"：它证明的是"在当前注入下，一个不是用事务层、而是用内部加权保护自己的系统没有被打坏"，恰好支撑"必须先判退化再动手"的论点。
- 但必须同时写明：视觉项惰性、注入距离 0.35 m、缺 degraded+noimg。否则"FAST-LIVO2 免疫"会被读成"多模态自然免疫 LiDAR 退化"，而数据不支持这个结论。
- Action Item 8.1 的原始假设（污染 VoxelMap 深度 → 光度项被带歪）**没有被检验，也没有被否证**。
