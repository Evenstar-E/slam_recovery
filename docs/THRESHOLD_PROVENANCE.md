# 冻结阈值溯源表（2026-11-10 首版）

目的：回答"这个数是从哪来的、有没有和实测分布对过"。`tau_info` 的教训是——一个从未与实测量级对照过的常数，只有在**它第一次成为唯一失败腿**时才会暴露，而那时已经烧掉若干轮运行。

## 规则（从此生效）

1. 任何冻结阈值，**第一次成为某次运行的主要失败腿时**，必须把它的值与该项的**实测分布**并列写出（分位/范围），不能只写"未通过"；
2. 若阈值落在实测量程**内部**，必须给出判别方向（阈值两侧分别代表什么），因为落在内部意味着"它决定结果"；
3. 每个阈值都要有来源标注：`CALIBRATED`（有标定记录）/ `INHERITED`（设计文档给定，无标定）/ `UNKNOWN`；
4. 测试夹具不得只按阈值的量级构造输入——至少有一个夹具使用**实测量级**的数值，否则测试只能证明"阈值能通过"，不能证明"阈值有判别力"。

## 结论

- 唯一被证明**方向错误**的是 `tau_info`；
- `tau_val_nis` 与 `sigma_tol` 目前都远高于实测量级，**不是错误，但也没有被验证过判别力**——它们只要不成为约束就不会暴露问题；
- 测试夹具（`info_after` 取 diag 40–60）全部按阈值量级构造，这是 `tau_info` 长期未被发现的直接原因之一；下一步至少加一个**按实测量级（after≈4.5）**构造的夹具，用来说明判据在那里的行为。
