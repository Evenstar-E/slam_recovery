# NIS σ 标定（2026-11-10）

只回答一件事：**σ 应该取多少，才能让预先声明的健康段上 NIS 中位数等于 1**。
不改任何阈值、不改 `nis_allowance_k`、不在代码里改 σ。结果 `nis_sigma_results.json`，
脚本 `nis_sigma_calibration.py`。

## 1. 为什么可以离线换算

`compute_disjoint_holdout_point_to_plane_nis` 返回 `mean((residual / σ)²)`；残差截断固定在
2.0 m、覆盖率门限与 σ 无关。所以 **NIS 严格正比于 1/σ²**，目标中位数 1 给出闭式解：

```
σ* = σ₀ · sqrt(median NIS @ σ₀)
```

不需要新的宿主运行。

| 估计器 | 仅 `nis_reference == "node_map"`。`prev_scan` 是另一条估计路径（含 18 帧 warm-up，节点自述"健康是假设、本趟无证据"），**排除** |

| 为什么这样判健康 | 注入窗边界由注入器在跑之前定死，**与门的输出无关**；窗前的数据在物理上是干净的 |

**σ 不改变这个候选的结果**，因为它不是被 NIS 拒的：`reentry_pos_jump_m = 0.666 > 0.5`

NIS 比较之前。σ 只动 NIS 这一条腿。

## 5. 两条成因必须分开报

1. **σ 这条线可以闭合**：中位数 21.30 → 1.00，超限帧 168/168 → 3/168，两趟一致。
2. **但 σ\* ≈ 0.55 m 不是传感器噪声**：它是当前参考构造下"让残差分布归一"的等效值，
   是 0.12 的 4.6 倍。点到面拟合的测量噪声不可能到半米，所以这个数本身就说明
   **残差被参考几何放大了**。

   σ 标定**能让报警停止**，但它的解落在不物理的量级上。**不能**据此把 σ 改成 0.55 当作修复。
   `σ*` 与参考构造是耦合的：参考一改，σ\* 必须重算。

### 5.1 归属修正（2026-11-10）：点数上限那半**撤回**

r11070-c3 实测：把 NIS 参考从点数上限换成 **0.30 m 分辨率空间抽样**后，
点数 **1500 → 931**，NIS 中位 **21.57 → 24.05**——**没有下降**。

所以：

- 本文件 §5 原先写的"单关键帧 **+ 点数上限摊薄**"，其中**点数上限这半撤回**。
  本文件的数字不受影响（它们是在 cap 参考上量的），但附在数字后面的解释要改。
- 剩下的候选是：**参考在首次可判定时只有 2 个关键帧**（`confirmation_margin=2 s`，
  地图年龄太小），以及**扫描与 931 点参考之间的真实残差约 0.55 m**。
- 两者尚未判定：r11070-c3 将跑 **detection=off** 的"只长图不检测"诊断，看 NIS 是否随
  `trusted_keyframes` / `map_points` 增长收敛到 O(1)。收敛 → 问题在启动条件；
  不收敛 → 回到 σ / 残差定义。**两种情况下 0.5538 都不得沿用。**

### 5.2 两版参考不可比

| | 旧（本文件） | 新（r11070-c3） |
|---|---|---|
| 抽样 | 点数上限 | 空间抽样，0.30 m |
| `map_points` | **恒 1500** | **931** |
| `trusted_keyframes` | 恒 1 | 首判时 2 |
| NIS 中位 | 21.57 | 24.05 |
| σ\* | 0.5538 / 0.5522 | 未标定（等诊断） |

结果 JSON 的 `reference_variant` 字段按"健康段内 `map_points` 是否为常数"自动标注：
常数 = `point_cap`，随地图变化 = 其它抽样。两次标定分属两版，**不比 σ\* 数值**；
判"参考口径已换"用 `map_points` 分布本身。

## 6. 分箱口径（等 detection=off 那趟）

detection=off 的 NIS 是在**地图持续增长**过程中量的，与本文"冻结在 1500/931 点"的分布
**不是同一人口**。所以收敛判断按 `trusted_keyframes` 分箱，**不用全段中位数直接和 21.30 比**
——那会把"地图变大"和"启动太早"混进一个数。

结果 JSON 每条 run 都带 `nis_by_trusted_keyframes`，形如：

```json
"nis_by_trusted_keyframes": {"1": {"n": 168, "median": 21.301, "p90": 29.426, ...}}
```

本趟健康段 168 帧**全部落在 `trusted_keyframes = 1`**（这正是问题本身：地图在首判时只有 1 帧）。
新一趟应当出现 `1/2/3/...` 多个箱；判据是**箱内中位是否随箱增大而收敛**，不是箱间中位的高低。

### 7.1 尾部

`101+` 箱重标后 σ\*=0.5329 时，261 帧里 73 帧（28%）超过检测限 2.074：

- **全部在 onset 之后**（0 帧在前）；onset 前 65 帧的最大值是 33.56 → 重标后 1.70，**无一超限**；
- 起点在 **onset + 5.78 s**；对应 kf 244–382、`map_points` 7567–8588（稳定大图，不是地图切换）；
- 时间分布（2 s 桶，超限帧/总数）：

| rel onset | 0–2 | 2–4 | 4–6 | 6–8 | 8–10 | 10–12 | 12–14 | 14–16 | 16–18 | 18–20 |

**判定：这是真实退化，不是覆盖空洞，也不是配对错。** 依据是三条同时成立——时间上有界
（+6~+12 s 全超限，前后回落到阈值以下）、空间上落在大图稳定段（`map_points` 7.5k–8.6k 无跳变）、

**旧归档的对照**：本文件 §4 那个候选的拒绝腿与 NIS 无关，这里也再次印证——NIS 的尾部不是

### 7.2 但尾部**没有覆盖整个注入窗**

注入窗是 onset → onset+**19.84 s**（`room02_2x2_audit.json:window.end_ns`）。
超限区间只到 **+12 s**，+12~+14 s 衰减，+14 s 之后回到阈值以下——
**注入窗最后约 6 s 没有被 NIS 标出**。

这条不能靠调 σ 解决（σ 是全局缩放，改它只会整体平移阈值，不会让尾部的形状变成窗的形状）。
它需要注入的**severity 时间线**才能判断是"退化在后半段自洽"还是"估计器漏检"；
该时间线不在本文件的数据里，记为 `UNCONFIRMED`。

### 7.3 结论边界

- **σ 标定**：作为"给定参考规模下把中位归一到 1"的描述，**闭合**；但它不是单一常数，
  且大图值与早先的 0.5538 不是同一测量。
- **尾部**：**解释得了**——真实退化，有界。
- **检测可用性**：**不结论**。按你的口径，可用性由尾部决定：这里尾部只覆盖注入窗的前 ~2/3，
  所以"能报警"不等于"能覆盖"。位置分布做不了：`frame_diagnostics` 不带位姿，
  该趟 receipt 的 `output` 为 null，没有输出 bag 可回溯。

## 8. 检测器重放：σ=0.533 下第一次报警在哪

用归档逐帧 NIS 重放检测器（`JointHealthDetector` 原样调用，不改任何阈值/配置），
`nis_q90 = nis × 1.35`，只判定 `nis_reference == "node_map"` 的帧（与节点 warm-up 策略一致：
没有参考就不判定）。

**先验证重放本身**：在阶段一那趟（`...2941380`）上取 σ=0.12，重放得到第一次隔离
`ts=1627643742844584942`，与该趟 receipt 记录的 `trigger_ts_ns` **逐位相同**。
重放机制可信，再看诊断趟。

### 8.1 结果（`...2974473`，detection=off）

| σ | 首次报警（SUSPECT） | 首次隔离（dwell=2） |
|---:|---:|---:|
| 0.4405（21–50 箱标定） | **−16.843 s** | **−16.709 s** |
| **0.5329（101+ 箱标定）** | **−16.843 s** | **−16.709 s** |
| 0.605 | −16.843 s | −16.709 s |
| 0.610 | −16.843 s | 6.118 s |
| 0.620 | 5.984 s | 6.118 s |
| 0.700 | 6.118 s | 6.185 s |
| 0.884（1–2 箱标定） | 6.386 s | 6.519 s |
| 1.200 | 6.386 s | 6.519 s |

**按你的判据，σ=0.5329 落在第一条分支**：第一次报警在 onset **之前 16.843 s**，
第一次隔离在 onset **之前 16.709 s** —— 检测在本配置下不可用。

原因可定位到帧级：前两个被判定帧是 kf 19 / kf 20，`map_points=932`、`trusted_keyframes=2`，
原始 NIS **55.045 / 53.490**；在 σ=0.5329 下缩放为 **2.791 / 2.712**，都高于检测限 2.074，
连续两帧触发 dwell=2，于是隔离。

### 8.2 但"任何单一 σ 都会在某一端失配"这句话，这批数据不支持

交叉点在 **σ ≈ 0.609**（解析式 `0.12·√(53.49/2.074)`，与重放一致）。也就是说：

- **σ ≥ 0.62 时，onset 前完全不报警**，第一次报警落在 **+5.98 ~ +6.39 s**，在注入窗内；
- 一直到 σ=1.2 仍然在 +6.4 s 附近报警（这批退化太大，上界在这份数据里测不到）。

所以准确的说法不是"没有单一 σ 可用"，而是：**按大图中位归一定出来的 σ（0.44–0.57）落在启动要求之下**。
大图目标与启动要求相差约 12–15%，而这个差距的方向是固定的——**地图越大，标定值越小，越早误报**。

需要的代价是明确的：取 σ≥0.62 时，大图中的位数会被压到 0.58–0.76（而不是 1），
即"以中位归一到 1"这个目标本身在启动段是不合适的。

### 8.3 对"是否继续投入检测线"的含义

- 误触发**不是 σ 标定能修的**，因为正确的 σ 由**启动段**（2 关键帧、932 点参考）决定，
  不是由大图决定；两种目标不可能同时满足。
- 但检测**也不是结构性不可用**：σ≥0.62 时它在本趟的 +6.0 s 报警，落在窗内。
- 真正的约束还是 §7.2 的覆盖率：即使 σ=0.62，报警从 +6.0 s 起、到 +12 s 止，
  而注入窗到 +19.8 s。**覆盖率是独立于 σ 的问题。**

### 8.4 边界

- 只重放了 **NIS 分支**：归档 `frame_diagnostics` 不带 FIM，`min_eig_*` 被置为不报警值。
  若真实运行里几何分支也会报警，首次报警可能更早——但那只会加强"不可用"的结论，不会反转。
- `prev_scan` 参考的帧不参与判定（节点 warm-up 策略），共 28 帧。
- 1–2 箱只有 **2 帧**，0.884 这个值不是标定，只是"恰好能压住启动报警"的数值。
