## 10. 四格 2×2 host 结果（独立复算，`evaluate_2x2_runs.py`）

八个原生重估包（每格 2 次）逐包读位姿、与 room_02 GT 关联后整轨迹 SE(3) 拟合（`FULL_ALIGNMENT_DIAGNOSTIC`）。窗内 199/199 帧全部有 75 ms 内位姿，GT 关联 732–778 帧。

| 格 | r1 ATE | r2 ATE | 判定 |
|---|---:|---:|---|
| O（oracle 基座） | **0.082 m** | **15.441 m** | 不稳定 |
| O+F（+1,265 残留） | 521.782 m | 15.551 m | 两次 fail |
| O−B（−23,607 误删） | 47.824 m | 20.269 m | 两次 fail |
| O+F−B（actual） | 484.925 m | **0.254 m** | 不稳定 |

**预声明规则判定：`NOT_A_CLEAN_INTERACTION`。** 组合格两次不同侧，两个单因素格反而都稳定 fail；连 oracle 基座 O 都在 0.082 与 15.4 m 之间跳。因此本轮**不能**把失效归给任一单因素，也不能称交互——宿主运行方差（采样期 load 数百）足以让同一格跨过 1.0 m 判据。

**对旧结论的影响**：此前 E_actual 单次 315.16 m vs E_oracle 0.074 m 得出的"过滤器是原因"不再成立——actual 格重复中出现 0.254 m。该结论降级为"单次运行观察，重复后不复现"。

**宿主侧独立复算**（`d2b1cf8`，共同集 323、每格 326/323 可用帧）给出同一结论，数值差来自 GT 关联集与序列对齐：

| 格 | ATE r1 / r2 | 冻结前缀协议 r1 / r2 | coverage r1 / r2 | patch unsupported r1 / r2 |
|---|---|---|---|---|
| O | 0.072 / 14.439 | 3.812 / 24.423 | 0.9988 / 0.6805 | 0.0073 / 0.6838 |
| O+F | 593.026 / 14.872 | 742.865 / 24.585 | 0.6900 / 0.6934 | 0.6771 / 0.6656 |
| O−B | 48.847 / 19.673 | 75.131 / 31.957 | 0.6949 / 0.6949 | 0.6492 / 0.6567 |
| O+F−B | 554.561 / 0.301 | 687.198 / 3.736 | 0.6963 / 0.9988 | 0.6456 / 0.0102 |

两种模式清晰可见：好模式 coverage 0.9988 / unsupported 0.007–0.010（O r1、O+F−B r2），坏模式 coverage≈0.69 / unsupported≈0.65（其余六次）。**好模式在 O 与 actual 各出现一次，与臂无关**，即宿主在这条序列上双稳。

**判定口径更正**：预声明 `fail_rule` 写的是 `ate_full_alignment_diagnostic_m`，而协议量是 `ate_frozen_prefix_protocol_m`——预声明本身选错了变量，但不能在看到结果后改用更有利的口径。两种口径并列：

- **预声明口径（diagnostic）**：`NOT_A_CLEAN_INTERACTION`；O 与 O+F−B 分叉，故"方差主导"。
- **协议口径（post-hoc，不替换判定）**：八次全部 >1.0 m（3.74–742.9 m），四格全部两次失败 → 仍无交互，但不是"时好时坏"，而是**没有一次达到协议精度**；该口径下"方差主导"不成立。

结论：**交互在两种口径下都不成立**；方差是否主导取决于口径，不能只报有利的一个。序列的协议精度整体不足，应先解决宿主/初始化问题。今后预声明必须直接写协议量，诊断量只作灵敏度。

**限定**：GT 只覆盖部分轨迹（732–778/785 匹配）；诊断 ATE 为整轨迹一次拟合，对发散后再收敛敏感；八次运行未做受控负载。
